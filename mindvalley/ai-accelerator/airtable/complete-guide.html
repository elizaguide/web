Database Fundamentals

  • Tables = Lists of the same type of item (posts, team members, projects)
  • Records = Individual items in your list (horizontal rows)
  • Fields = Characteristics/attributes of each item (vertical columns)
  • Relations = Connections between different tables

🚀 Step-by-Step Implementation

Phase 1: Set Up Your Foundation

⏰Timeline: Week 1-2

  1. Sign up for Airtable (free plan is sufficient)
  2. Enable AI features in your workspace settings
  3. Access the training template: Use the shared base link from class
  4. Practice with demo data before building your own

Phase 2: Create Your First AI App

  1. Click "Create a base"
  2. Select "Build an app with Omni"
  3. Provide detailed context prompt (not just "social media app")
  4. Answer follow-up questions for customization
  5. Review the auto-generated structure

Phase 3: Build AI Field Agents

  1. Navigate to your table and click the "+" button
  2. Select "Build a field agent"
  3. Choose response type:
    • Long text for content creation
    • Single select for categorization
    • Number for scoring/analysis
  4. Configure settings:
    • Enable/disable internet search
    • Select AI model (use Claude 4.5 Haiku for cost efficiency)
    • Set auto-run preferences

Phase 4: Write Effective Prompts

Structure: Role + Task + Context + Output Requirements Example: "You're an expert social media marketer. Create a viral LinkedIn post that: - Extracts the most interesting idea from: [Blog Post Field] - Optimizes for target audience: [Target Audience Field] - Uses engaging hooks and clear value propositions"

⚡ Pro Tips from the Training

Cost Management

  • Use Claude 4.5 Haiku for simple tasks (much cheaper)
  • Don't enable auto-run initially (avoid burning credits)
  • Test with small datasets first

Prompt Engineering

  • Context matters more than format - provide rich, relevant data
  • Reference fields dynamically using Insert Field button
  • Use multiple context sources (combine different database fields)

Database Design

  • Force data structure through field types (ensures reliability)
  • Link related tables for complex relationships
  • Start simple and add complexity gradually
