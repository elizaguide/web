1. System Overview

🎯 Architecture Philosophy

Scalable, event-driven architecture that supports people-first multi-level participation with real-time chat integration. Built for rapid iteration and seamless cross-platform experiences.

System Architecture Layers

Frontend Layer
React Web + React Native Mobile
↓ API Calls ↓
API Gateway
REST + GraphQL + WebSocket
↓ Business Logic ↓
Business Services
Auth, Networks, Groups, Discussions
↓ Data Persistence ↓
Data Layer
PostgreSQL + Redis + GetStream

Core Principles

  • Event-Driven: Real-time updates across all clients using WebSocket connections
  • Microservices Ready: Modular design allows future service separation
  • API-First: All features accessible via REST/GraphQL APIs
  • Cross-Platform: Single API serves web and mobile clients
  • Third-Party Integration: Clean abstraction layer for GetStream and Mindvalley APIs

2. Technology Stack

🎨 Frontend

  • Web: React 18, TypeScript, TailwindCSS
  • Mobile: React Native, Expo SDK
  • State: Zustand + React Query
  • Chat: GetStream React SDK

🖥️ Backend

  • Runtime: Node.js 18+, TypeScript
  • Framework: Express.js with Helmet, CORS
  • API: REST + GraphQL (Apollo Server)
  • Auth: JWT + Passport.js

💾 Database

  • Primary: PostgreSQL 15+
  • Cache: Redis 7+
  • ORM: Prisma
  • Search: Full-text search (PostgreSQL)

🔌 Integrations

  • Chat: GetStream Chat API
  • Auth: Mindvalley OAuth/SSO
  • Storage: AWS S3 / Cloudflare R2
  • CDN: Cloudflare

🚀 Infrastructure

  • Hosting: Vercel (web) + Railway (API)
  • Database: Supabase / Railway PostgreSQL
  • Monitoring: Sentry + LogRocket
  • Analytics: Mixpanel + PostHog

🛠️ DevOps

  • CI/CD: GitHub Actions
  • Testing: Jest + Playwright
  • Linting: ESLint + Prettier
  • Type Safety: TypeScript strict mode
Tech Stack Rationale: Chosen for rapid development speed, excellent TypeScript support, and seamless integration with GetStream. This stack allows the team to move quickly while maintaining code quality and scalability.

Authenticate user with Mindvalley credentials or email/password

Get current user profile and permissions

Network Management

GET /api/networks
List user's networks with membership status

5. GetStream Integration

Channel Management Strategy

Level Channel Naming Channel Type Member Sync
Network network-{id}-{type} team Auto-sync on membership change
Group group-{id}-{type} team Auto-sync on membership change
Discussion discussion-{id} messaging Manual invite-only management

Integration Architecture

// GetStream Service Layer class GetStreamService { // Discussion Channel Creation async createDiscussionChannel(discussion: Discussion, creator: User) { const channelId = `discussion-${discussion.id}`; const channel = this.client.channel('messaging', channelId, { name: discussion.title, created_by_id: creator.id, members: [creator.id], custom: { level: 'discussion', discussion_id: discussion.id, group_id: discussion.group_id, invite_limit: discussion.invite_limit, finerminds_data: { group_name: discussion.group.name, network_name: discussion.group.network.name } } }); await channel.create(); await this.sendWelcomeMessage(channel, discussion); return channel; } // Member Synchronization async syncDiscussionMembers(discussionId: string, memberIds: string[]) { const channelId = `discussion-${discussionId}`; const channel = this.client.channel('messaging', channelId); // Add new members await channel.addMembers(memberIds); // Send notification about new members await this.sendMemberJoinedNotification(channel, memberIds); } // Webhook Processing async processWebhook(event: GetStreamEvent) { switch(event.type) { case 'message.new': await this.handleNewMessage(event); break; case 'member.added': await this.handleMemberAdded(event); break; case 'channel.updated': await this.handleChannelUpdated(event); break; } } }

Performance Optimizations

  • Channel Caching: Cache frequently accessed channels in Redis
  • Batch Operations: Group member additions/removals for efficiency
  • Lazy Loading: Load channel history only when needed
  • Connection Pooling: Reuse GetStream client connections

6. Security & Privacy

Authentication & Authorization

🔐 JWT Implementation

  • Short-lived access tokens (15 min)
  • Refresh token rotation
  • Role-based permissions in JWT payload
  • Automatic token validation middleware

🛡️ Permission System

  • Network-level access control
  • Group membership validation
  • Discussion invite-only enforcement
  • Admin action authorization

🔒 Data Protection

  • HTTPS/TLS 1.3 encryption
  • Database connection encryption
  • PII data pseudonymization
  • GDPR deletion compliance

🚨 Security Monitoring

  • Rate limiting on all endpoints
  • Suspicious activity detection
  • Audit logging for admin actions
  • Real-time security alerts

Privacy Controls

GDPR Compliance Requirements:
  • Right to data portability (export all user data)
  • Right to erasure (complete data deletion)
  • Data processing transparency (clear privacy policy)
  • Consent management for data collection

7. Performance & Scalability

Performance Targets

Metric Target Monitoring Method
API Response Time < 200ms (95th percentile) APM monitoring + health checks
Database Query Time < 50ms (95th percentile) Query performance monitoring
Real-time Message Latency < 100ms GetStream analytics + WebSocket monitoring
Page Load Time < 2s (LCP) Core Web Vitals monitoring
Uptime 99.9% Synthetic monitoring + alerting

Scaling Strategy

Horizontal Scaling Plan:
  • Phase 1 (0-10k users): Single server deployment with connection pooling
  • Phase 2 (10k-100k users): Load balancer + multiple API servers + read replicas
  • Phase 3 (100k+ users): Microservices architecture + CDN + database sharding
